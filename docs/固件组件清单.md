## 三、结论

- 库内现有组件在设置应用里**基本都能找到对应**，没有明显漏掉的「基础」组件；
- 真正缺的是**设置类**的复合组件：选项卡片、可展开分组、带标签滑杆、选项选择器、贴底确认条、
  图案解锁 —— 这些在设置里都是独立实现，值得合并进库；
- **其余 50 个左右的锤子应用尚未排查**（桌面、锁屏、联系人、文件管理、输入法、安全中心……），
  里面大概率还有更多组件。

## 四、下一步建议

按「复用价值 / 实现成本」排序，建议先做：

1. `SmartisanLabeledSlider`（设置里有 5 处重复实现，合并收益最大）
2. `SmartisanOptionCard` + `SmartisanExpandableGroup`（设置页骨架）
3. `SmartisanOptionSelector`（横排/竖排两套合一）
4. `SmartisanBottomConfirmBar`、`SmartisanLockPattern`
5. 再排查 `LauncherSmartisanNew`、`KeyguardSmartisan`、`FileManagerSmartisan`

## 五、Smartisan framework 里的组件（重点）

### 4. 规范的缓动曲线（framework interpolator）

framework 里有一套完整的锤子缓动族，共 25 个：

```
smartisan_{sine,quad,cubic,quart,quint,circ,back}_{in,out,in_out}
accelerate_decelerate  decelerate_cubic  decelerate_quad  decelerate_quint
```

其中 `decelerate_cubic` 已解码确认是 `DecelerateInterpolator(factor = 1.5)`，
即 `1 - (1 - t)³` —— 与本库 `SmartisanDecelerateCubic` **完全一致** ✅。

但 `smartisan_*_out` 这些是 framework 自己的 `smartisan_tween_interpolator`，
XML 里只有一个 `category` 数字（例如 `smartisan_cubic_out` = `category=8`），
**具体曲线实现在 framework 代码里**，本库拿不到，因此没有照搬 ——
本库目前用的是自己整理的余弦 / 二次 / 三次缓动。

## 六、排查结论与工作量

| 范围 | 数量 | 已排查 |
| --- | --- | --- |
| 锤子自有应用 | 62 | 12 |
| framework layout | 162 | 0 |
| framework anim | 46 | 4（转场相关） |
| framework interpolator | 25 | 1 |

**结论**：本库现有的通用组件（列表、标题栏、弹窗、开关、输入、时钟）方向是对的，
但覆盖面远小于锤子实际的组件体系。缺口主要有三块：

1. **framework 的列表行矩阵**（2 行 / 3 行 × 左右位置 × 复选框 / 开关 / 箭头）—— ✅ 已补齐；
2. **framework 的日期时间选择器与日历** —— ✅ 已补齐（选择器 + `SmartisanCalendar`）；
3. **剩下 50 个应用**里的组件（桌面、锁屏、联系人、文件管理、输入法、安全中心……）—— 待推进。

要补齐这些，建议按 framework → 设置 → 桌面 / 锁屏 的顺序推进，
因为 framework 里的组件被所有应用复用，收益最大。

## 七、framework 代码的获取方式（已解决）

之前以为 framework 代码只在 vdex 里、拿不到 —— **结论是错的**：

| 文件 | 实际情况 |
| --- | --- |
| `framework/boot-smartisanos.vdex` | **空壳**（2361 字节），没有代码 |
| `framework/boot-smartisan-framework-tnt.vdex` | **空壳**（141 字节） |
| `framework/smartisanos.jar` | ✅ **里面是 `classes.dex`，1.67 MB，1224 个类** |
| `framework/smartisan-framework-tnt.jar` | 同上的 TNT 版本 |

所以框架代码是拿得到的：

```bash
unzip -o smartisanos.jar classes.dex
java -cp ... # 或用 baksmali / jadx 反编译
```

仓库里附了一个轻量扫描脚本 `tools/dexscan.py`，直接解析 DEX 的 class_def 表，
列出所有「父类是 View / ViewGroup / 各类 Layout / Dialog / Adapter」的类，不需要真机也不需要 jadx：

```bash
python3 tools/dexscan.py classes.dex
```

#### 锁屏应用清扫结论（`KeyguardSmartisan`）

原版锁屏是 `sharedUserId="android.uid.system"` 的 `coreApp`，绝大多数类绑系统服务（指纹 HAL、TNT 桌面、`WindowManager` 浮层、
`KeyguardUpdateMonitor`），但它的**视觉件**是可以分离出来移植的。逐类过完 160 个自有类后的结论：

**已移植（1 套）**

| 原版 | 库内对应 | 说明 |
| --- | --- | --- |
| `widgets/flipnumber/FlipNumber` + `FlipDownInterpolator` + 8 个 `*Animation` / `*Interpolator`，`widgets/WirelessChargingTime`、`FlipClock` | `SmartisanFlipCard` + `SmartisanFlipClock` | 无线充电时的翻页时钟：两位数卡片（十位 + 个位）、上下半折页、铰链、三层覆盖层、1000ms ease-out-elastic 翻页曲线；`clock_theme_style = 0`（默认）就是这一套 |

**待移植（有价值的视觉件，按优先级）**

| 原版 | 行数 | 说明 |
| --- | --- | --- |
| `widgets/KeyguardLockPatternView` | 883 | 锁屏图案解锁：`extends View` 自绘 3×3 点位、正确 / 错误两套配色（含「室内模式」配色）、路径 `Path` 渐隐，库内还没有图案锁组件 |
| `RollingClock` / `RollingClock2` / `LCDClock` + `layout/rolling*_charging_clock.xml`、`lcd_charging_clock.xml` | 164 / 168 / 112 | 另外三种无线充电时钟样式（`clock_theme_style` 1 / 3 / 2）：滚动数字、第二个滚动版、LCD 点阵；素材与尺寸都在，做法同翻页时钟 |
| `wheel` 系列的 `widgets/QuickLaunchPickerView` + `QuickLaunchIndicatorView` + `PickerItem` | ~700 | 锁屏右下角快捷启动的扇形选择器（带指示点与缩放动画） |
| `widgets/WaveView` | — | 充电波纹动画 |
| `widgets/ProgressableButton`、`widgets/MarqueeableTextView`、`RoundCornerLayout` | | 带进度的按钮、可跑马灯的文本、圆角容器（小件，收益低） |

**不移植（绑系统服务 / 只对锁屏有意义）**

| 原版 | 原因 |
| --- | --- |
| `KeyguardViewMediator` / `KeyguardViewManager` / `KeyguardHostView`（4492 行）/ `KeyguardUpdateMonitor` / `KeyguardViewBase` | 锁屏宿主与状态机，系统 `WindowManager` + `KeyguardService` 直接驱动 |
| `KeyguardActivityLauncher` / `FingerprintUnlockController` / `KeyguardFingerprintManager` / `faceid.*` | 指纹 / 人脸解锁，绑 HAL 与系统权限 |
| `pin.*`（`PinRootView` 1270 行、`PinManager`、`PinnedTaskView`…）、`widgets/tpager.*` | TNT 桌面（次要屏）的「钉住任务 / 快捷页」，依赖系统跨屏服务 |

| `keyguard/anim/*`（`DynamicAnimation` / `SpringAnimation` 等） | 就是 support 库 `androidx.dynamicanimation` 的打包副本，Compose 侧有等价 API |

结论：**framework 层覆盖率是应用层覆盖率的超集**这条判断在锁屏上成立 —— 锁屏里 55 个 `extends View/ViewGroup` 的类，
除了翻页时钟这一套与上面列出的「待移植」，其余都能在库里找到对应实现或本来就是系统专用。



这一节是「应用清扫」的结论：把 framework 里所有自定义 View / ViewGroup（93 个类，`grep extends View|ViewGroup|*Layout|*View`）逐个对照库内实现，分成「已覆盖 / 不移植 / 待移植」三类。
应用 APK 可以从系统 dump 仓库按需取（见上），但逐应用清扫是另一条更大的线：framework 是所有应用共用的那一层，覆盖率本身就是应用侧组件覆盖率的超集；应用特有的组件按「已清扫的应用」一节逐个补。
