## 二、迁移时的主要差异

### 1. 不再有 `R.drawable.*` 依赖

原实现大量依赖 `R.drawable` 里的 selector、NinePatch 和位图。
smartisanx 全部改为 Compose 绘制，因此：

- 不需要再往 `res/drawable-*` 里放资源；
- 不再有 `values-night/drawable-night` 成对维护的问题；
- 颜色、圆角、阴影全部来自主题，深浅色自动适配。

如果确实需要使用自己的 drawable（例如应用内的品牌图标），
仍可以使用 `rememberSmartisanDrawablePainter` 与 `Modifier.smartisanDrawableBackground`，
它们保留了 selector 状态与 NinePatch 拉伸。

### 2. 组件不再读取 `R.dimen.*`

原实现的尺寸来自 `R.dimen`，本库改为 `SmartisanDimens` 常量 + 显式参数。
迁移时把 `dimensionResource(R.dimen.xxx)` 换成对应的参数或常量。

### 3. 组件不再自带业务回调

原实现里混入了业务回调（如 `onQueueChanged`、`onCityDeleted`）。
本库只保留纯粹的 UI 回调（`onClick`、`onCheckedChange`、`onMove`、`onDelete`），
业务状态由使用方持有。

### 4. 按压反馈统一

原实现分别处理「列表按压蓝色高亮」「图标 1.33 倍放大」「按钮收缩」等反馈。
本库把共性抽成 `collectSmartisanPressedAsState` + 各组件的按压态绘制，
行为保持一致，但只需要维护一处。

## 三、迁移检查清单

- [ ] 用 `SmartisanTheme` 包裹根界面
- [ ] 把 `R.dimen` 引用换成 `SmartisanDimens` 或组件参数
- [ ] 把 `R.color` 引用换成 `LocalSmartisanColors.current` 的语义色
- [ ] 把 `Text` / `BasicText` 换成 `SmartisanText`
- [ ] 把 Material `Switch` / `Checkbox` / `Button` 换成对应的 smartisanx 组件
- [ ] 删除不再使用的 drawable / values-night 资源
- [ ] 用示例应用（`sample` 模块）对照检查视觉是否一致
