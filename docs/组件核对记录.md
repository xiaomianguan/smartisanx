# 组件核对记录

**中文** · [English](ComponentVerification.md)

这份文档记录把 smartisanx 的组件逐个对照原始实现核对的结果：
对照对象优先是三个复刻项目（同为 Compose，可直接比对），
其次是从原厂 APK 反编译出来的自定义 View 与资源。

核对方法：对每个组件找出原始实现，逐项比对**尺寸常量、几何、时长、缓动、手势物理与所用资源**，
而不是只看「像不像」。

## 二、已知差异（有意为之）

这些地方本库与原版**故意不同**，都已在对应组件的 KDoc 里注明：

| 项目 | 原版 | 本库 | 原因 |
| --- | --- | --- | --- |
| 标题栏高度 | 音乐 50dp / 天气与时钟 48dp | 48dp | 三个应用本身就不一致，取多数；需要 50dp 时传 `contentHeight = 50.dp` |
| 深色模式 | 原版没有 | 实验性，默认关闭 | 由复刻项目新增，且原版素材只有约 19% 带夜间变体 |
| 文字 / 提示色 | `editor_text_color` 等取自 framework | 主题语义色 | 这些资源只在 Smartisan framework 里，拿不到 |
| 光标条 | nine-patch `edittext_cursor_bbackground` | 主题 `accent` | Compose 的 `cursorBrush` 只接受 `Brush` |
| 清除按钮显隐 | `setVisibility` 瞬时切换 | 默认 200ms 淡入淡出 | 可传 `animateClearIcon = false` 完全对齐原版 |
| 滚动条 | 系统默认滚动条 | 自绘细滚动条 | 原版没有对应位图 |
| 文字标签栏 | 原版没有文字标签栏 | 自绘 | 原版标签切换都是图标式 |
| 分组标题底色 | framework `#f5f5f5` | 主题 `surfaceRaised`（浅色 `#F7F8F9`） | 深色模式要跟随主题；浅色下与原版相差 ≤3 级灰阶 |
| 分组标题文字色 | framework `#4c000000`（30% 黑） | 主题 `textTertiary`（`#66000000`，40%） | 用主题语义色，并与 `SmartisanGroup` 的分组标题保持同一档 |
| 行说明文字色 | framework `#80000000`（50% 黑） | 主题 `textTertiary`（`#66000000`，40%） | 与 `SmartisanListItem` 的说明文字同一档，避免同一库内两套灰 |
| 行禁用文字色 | framework 不透明 `#bababa` | 主题 `textDisabled`（`#4c000000`，30% 黑 ⇒ 白底约 179） | 用主题语义色；与原版相差不到 8 级灰阶 |
| 编辑行提示文字色 | framework `#26000000`（15% 黑 ⇒ 白底约 217） | 主题 `textHint`（`#DBDBDB` ⇒ 219） | 用主题语义色；只差 2 级灰阶 |
| 带图标滑杆的端点图标 | 两个图标「要么都给、要么都 GONE」（`leftIconRes > 0 && rightIconRes > 0` 才 `setImageResource`） | 两个独立可选槽位，给哪个画哪个 | 槽位式 API 更自然，原版那样更像实现疏漏 |
| 滑杆禁用时的端点图标 | 只切换滑块素材，图标不跟着变灰 | 同左（库不做任何处理） | 保持原版行为；图标要不要变灰由调用方决定 |
| 复合标题栏中槽的自然宽度 | Android 先按 `wrap_content` 量一次再决定居中 | 用 `maxIntrinsicWidth()` 取自然宽度（Compose 只允许量一次） | 自定义 `Layout` 没实现固有测量时按「装不下」处理 |
| 复合标题栏右侧按钮 | 内置最多 10 个 `SmartisanButton`，相邻 `-6dp` 压住 | 不做按钮容器，`trailing` 槽自己排 | 原版那套按钮样式与图标表已由 `SmartisanButton` / `SmartisanIconButton` 覆盖，容器逻辑没必要内建 |
| 消息输入栏文字 / 提示色 | framework `editor_text_color`（#cc000000）/ `editor_hint_text_color`（#26000000） | 主题 `textPrimary` / `textHint` | 跟随 smartisanx 深色主题，与其它输入类组件一致 |
| 消息输入栏的文字监听 | `beforeTextChanged` / `onTextChanged` / `afterTextChanged` 三段回调 | 合并为 `onValueChange` | Compose 只有单一变化回调，前两段没有对应物 |
| 消息输入栏的导航栏 insets | 原版不处理（各 App 布局自己负责） | 同样不处理，由调用方加 | 保持原版的分工 |
| 进度弹窗的圆环动画 | 用平台默认的不确定 ProgressBar（`ProgressBarCircleStyle.Medium` 没指定 drawable） | 用 ROM 里那张 48dp 圈素材匀速旋转（1s/圈，可传参改） | Compose 没有平台不确定动画，素材与尺寸都照原版 |
| 进度弹窗的确定进度 | `setProgress(int)` 是空实现 | 同样只做不确定态 | 原版本身就不支持确定进度 |
| BHM 行的禁用态 | `BHMDrawerItem.isEnabled()` 只挡点击，变灰靠各 App 自己传色 | 同样只挡点击与图标 selector，标题灰由 `SmartisanBhmItem.titleColor` 决定 | 保持原版分工 |
| BHM 的分组标题色 | `bhm_header_view_color` #4d000000（30% 黑） | 主题 `textTertiary`（40% 黑） | 跟随深色主题 |
| BHM 的列表底色 | 布局写死 `@android:color/white` | 主题 `surface` | 跟随深色主题 |

## 三、资源与字体的核对

- **图形资源**：全部来自原厂 APK 的 `res/drawable*` / `mipmap*`，按内容去重，
  保留原始文件名与夜间 / 多密度限定符目录。
- **字体**：正文用 Smartisan OS 系统字体 `Smartisan Compact CNS`，
  取自坚果 R2 官方 ROM 转储的 `system/system/fonts/`；
  字体内嵌名称与字重已通过解析 OTF `name` 表核对（family = `Smartisan Compact CNS`）。
- **图标**：把 selector 链解析到最底层位图后分类，
  排除了 2195 个 nine-patch 按钮底图与 1647 张大图，只保留真图标。

## 四、真机逐像素核对

环境是 macOS + 一台 1264×2800 @ 560dpi 的测试机（即 **3.5px/dp**），
所以现在可以把组件装到真机上截图、**按像素反推实际尺寸与颜色**，不再只靠读数值。
做法：对截图做行 / 列扫描（取第一个与最后一个「有墨」的像素、色带边界与灰度），
再与 framework 的 dimens / colors 对照。

### 截图颜色是 Display P3

真机截图里的彩色像素是 **Display P3** 编码，不是 sRGB：主题 `accent` `#E64040` 在截图里读出来是
`#D44E47`，把 sRGB 值换算到 P3 坐标（`(230,64,64) → (212,78,71)`）与实测完全吻合。
也就是说**不要拿截图的彩色去改代码里的颜色**——几何和灰阶不受影响（中性灰在 sRGB / P3 里坐标相同），
彩色则要按 P3 换算后再比。
